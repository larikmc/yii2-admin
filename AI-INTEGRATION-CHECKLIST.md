# AI Integration Checklist (Admin UI)

Этот документ нужен для нейросети как строгий стандарт при интеграции `larikmc/yii2-admin` в новый проект.

Цель: чтобы модель не забывала базовые UI-правила и не требовала повторных уточнений про фон, заголовки, badges и grouped action-кнопки.

## 0) Zero-Configuration: правила в urlManager и errorHandler НЕ ТРЕБУЮТСЯ

1. **Не прописывать правила админки в `urlManager['rules']`**:
   - Все маршруты админки (`dashboard`, `login`, `logout`, `auth/*`, `rbac/*`, `profile`, `ui-kit`, `error`, `clear-cache`) регистрируются **автоматически** в самом пакете (`Bootstrap` и `Module::getDefaultUrlRules()`).
   - Секция `'rules'` в файле `backend/config/main.php` должна содержать **ТОЛЬКО** проектные маршруты (например, каталога, новостей, заказов).
2. **Не переопределять `errorHandler['errorAction']`**:
   - Пакет автоматически перенаправляет ошибки на встроенный шаблон `admin/site/error`.
3. **Не создавать дублирующих `baseUrl` путей**:
   - При `baseUrl = '/admin'`, генерация `Url::to(['/admin/site/ui-kit'])` и короткий путь `/admin/ui-kit` работают из коробки без дублирования `/admin/admin/...`.

## 1) Что сделать в первую очередь

1. Прочитать `README.md` (включая подробный раздел "UI guide") полностью.
2. Принять раздел "UI guide" в `README.md` как визуальный source of truth.
3. Проверить, что используется layout пакета:
   - `@larikmc/admin/views/layouts/main`
4. Проверить, что подключены asset-файлы пакета:
   - `src/assets/AppAsset.php`
   - `src/web/css/style.css`
   - `src/web/css/dashboard.css`
   - `src/web/js/dashboard.js`
5. Проверить страницу-эталон:
   - `/admin/site/ui-kit`

Если любой пункт выше не выполнен, сначала исправить это, и только потом править конкретные экраны.

## 2) Обязательные UI-правила (MUST)

1. Заголовок страницы (`H1`) должен быть только один: в topbar.
2. Внутри контента дублирующий `H1`/header не показывать.
3. Для экранов на `AdminPage` использовать:
   - `'showHeader' => false`
4. У страницы всегда должен быть заполнен `$this->title`.
5. Не возвращаться к старым bootstrap-alert блокам как основному паттерну.
6. Использовать bootstrap-семантику кнопок:
   - `.btn`, `.btn-primary`, `.btn-secondary`, `.btn-success`, `.btn-danger`, `.btn-warning`, `.btn-info`, `.btn-light`, `.btn-outline-*`
7. Использовать bootstrap badges:
   - `.badge.text-bg-*`
8. Не использовать legacy-статус-классы, если можно заменить на `.badge.text-bg-*`.
9. Фоны/поверхности должны соответствовать текущему UI kit (panel/glass стиль), не плоский дефолт bootstrap.
10. Для таблиц `GridView` action-кнопки должны быть grouped, без щелей между сегментами.
11. Таблицы `GridView` должны использовать базовые стили `.grid-view .table`:
    - внешняя рамка со скруглением (`border-radius: 14px`, `border: 1px solid var(--stroke)`) на самой `table`, без дублирующих рамок;
    - блок `.summary` («Показаны записи...») оформляется компактным текстом `12px` без разделительных линий;
    - нижняя строка таблицы не должна задваивать нижнюю границу (`border-bottom: 0 !important`).

## 3) ActionColumn, удаление и пагинация (Автоматизировано)

Начиная с версии 2.1.3 стили GridView работают «из коробки» для любого стандартного Yii2 CRUD:

1. **Авто-стилизация стандартного Yii2 Gii CRUD**:
   - Больше **НЕ ТРЕБУЕТСЯ** вручную прописывать класс `'sz-row-action'`, класс ячейки `'action-column'` или переопределять стандартный `template`.
   - Стандартный `yii\grid\ActionColumn` со стандартными SVG-иконками ядра Yii2 (`eye-open`, `pencil`, `trash`) автоматически объединяется в монолитную группу кнопок (`.btn-group-action`) с аккуратными размерами `33x30px`, скруглением углов `9px` и выравниванием по центру.
2. **Кнопка удаления**:
   - Автоматически распознает `data-method="post"` и `data-confirm` и переходит в danger-состояние (красный фон/текст) на hover в обеих темах.
3. **Пагинация GridView**:
   - Стандартный `yii\widgets\LinkPager` (генерируемый GridView) автоматически оформлен в компактный UI kit стиль (`32x32px`, скругление `8px`, primary активный элемент, полупрозрачные disabled-стрелки) с отступом `margin-top: 16px` от таблицы.
4. **Кастомные ActionColumn (при необходимости)**:
   - Если вы кастомизируете кнопки вручную, достаточно использовать стандартный `ActionColumn` либо класс `sz-row-action` с иконками `Material Symbols Rounded` (`visibility`, `edit`, `delete`).

## 4) Правила для Vue-экранов в проекте

Если в проекте есть админские экраны на Vue, применять те же правила:

1. Верхний `H1` только в общем topbar/layout-компоненте.
2. Внутри Vue-страницы повторный `h1` не рендерить.
3. Использовать те же токены/классы UI kit для фонов и панелей.
4. Для статусов применять `.badge.text-bg-*` (или эквивалентный компонент, дающий тот же визуальный результат).
5. Для row-actions повторять grouped-паттерн (`view/edit/delete`), delete hover = red.
6. Не смешивать “старый bootstrap вид” и новый admin UI на одной странице.

Минимальная проверка для Vue-файлов:

- нет второго `h1` в контентной зоне;
- кнопки и badges соответствуют UI kit;
- row-action delete красный на hover;
- фон и panel-слои визуально совпадают с `/admin/site/ui-kit`.

## 5) Definition of Done (проверка перед сдачей)

Перед завершением задачи модель обязана проверить:

1. На странице нет дублирующегося заголовка (`topbar H1` + контентный `H1` одновременно).
2. Кнопки используют bootstrap-классы UI kit, а не legacy-замены.
3. Статусы/метки оформлены через `.badge.text-bg-*`.
4. `GridView` action-кнопки визуально grouped.
5. У delete-кнопки hover-состояние danger (красный).
6. Изменения не ломают breadcrumbs/topbar.
7. Проверена страница `/admin/site/ui-kit` как эталон.

## 6) Типовые ошибки, которые нельзя повторять

1. Добавлять второй заголовок внутри `AdminPage`, забыв `'showHeader' => false`.
2. Копировать или вручную прописывать правила админки в `backend/config/main.php` в `urlManager['rules']`.
3. Использовать `ActionColumn` шаблон с пробелами (`'{view} {update} {delete}'`).
4. Не ломать стандартную разметку таблицы и пагинации внешними стилями.
5. Стилизовать delete как обычную кнопку без danger-hover.
6. Возвращать старые статусные классы вместо bootstrap badges.
7. Править локальную страницу без проверки, что asset bundle вообще подключен.

## 7) Короткий промпт для любой нейросети

Скопируй и используй как стартовый системный/рабочий промпт:

> Интегрируй изменения строго по `AI-INTEGRATION-CHECKLIST.md` и разделу "UI guide" в `README.md`.
> Обязательно:
> 1) Никаких лишних правил админки в `urlManager['rules']` (Zero-Config архитектура),
> 2) один H1 только в topbar (внутри контента без дубля, для `AdminPage` ставь `showHeader=false`),
> 3) bootstrap buttons и `.badge.text-bg-*`,
> 4) grouped action-кнопки `view/edit/delete` с `sz-row-action`, template без пробелов,
> 5) delete hover = red (danger),
> 6) визуально сверяйся с `/admin/site/ui-kit`.
> В конце дай отчет по каждому пункту DoD.
